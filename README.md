# Decision Companion

一个帮助用户在购物过程中看见条件代价、试探偏好边界并完成取舍的交互原型。

## 产品背景

对话式 AI 已经能够理解需求、补全信息并推荐商品，但用户经常仍然无法在多个合理候选之间继续推进。

此时缺少的往往不是更多商品信息，而是用户尚未明确：

> 自己愿意为哪项价值付出什么代价。

Decision Companion 在普通购物对话之外增加了一个决策层，让用户通过可逆操作观察限制条件、候选空间和推荐结果如何变化。

## 核心流程

```text
Conversation 对话层
用户表达需求，AI补全信息并形成推荐
        ↓
Peek
提示一个值得检验的取舍边界
        ↓
Decision 决策层
切换方案，观察候选、收益和代价变化
        ↓
确认取舍 / 保留底线 / 拒绝候选空间
```

## Demo 展示内容

- Conversation 对话态与轻量候选预览；
- Peek触发的四种典型场景；
- 从重量上限1.35kg切换到1.60kg；
- 候选数量、排序和首选实时变化；
- “得到什么 / 牺牲什么”的对照归因；
- 预览、确认、撤回和偏好回写；
- “这些都不合适，继续聊”的候选域拒绝出口；
- 可直接查看的评测证据与Bad Case记录。

## 评测摘要

| 评测部分 | 结果 |
|---|---:|
| Peek触发规则 | 15/15通过 |
| 候选与归因计算 | 16/16通过 |
| 状态转换路径 | 10/10通过 |
| 3人外部可理解性检查 | 12/15项可确认 |

10人探索性测试中，所有参与者都能表达“更在意重量”或“更在意性能”，但无人能够自行给出具体重量边界。决策层组5名参与者均能在操作后说清自己愿意“用什么换什么”。

该结果只用于验证机制、表达和方向性价值，不证明推荐更准确、用户满意度或购买转化率提升。

## 核心结论

> 决策层能够把一个已经存在但难以表达的取舍，变得可操作、可比较、可确认。前提是用户基本接受当前候选空间。它帮助用户形成可执行的偏好边界，不替用户决定应该购买哪一类产品。

## 本地运行

本项目为单文件原型，不需要安装依赖或启动服务器。

1. 下载 `index.html`；
2. 使用Chrome、Edge或Safari直接打开；
3. 点击右侧案例切换不同Peek触发状态；
4. 点击或上滑Peek进入决策层。
